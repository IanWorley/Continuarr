# Verify sync against real Plex and Jellyfin servers

Use this checklist to verify watched-state sync against real servers before treating v1 as complete. Fixture results from `.agents/skills/continuarr-test-session` do not count as real-server acceptance.

## Before you start

1. Use a Plex Media Server and a Jellyfin server that you are willing to modify. Every scenario changes watched status, so never run this against personal libraries.
2. Add at least three movies and one show with two or more episodes to both servers. Each test item needs the same IMDb, TMDb, or TVDb ID on both servers, no conflicting IDs, and no other item sharing that ID. Continuarr does not match by title and skips ambiguous items.
3. For the matching scenarios, pick two more shows that are on both servers. Use the metadata the servers already report. Do not edit IDs or switch metadata agents to create a case. Their episodes are test items too.
   - The **series show** reports the same IMDb, TMDb, or TVDb series ID on both servers, with no conflicting series ID. On at least one server, its episodes report no episode-level ID. In **Manual matching**, those episodes read "No metadata IDs provided". It needs regular episodes S01E01 and S01E02 on both servers. On each server, S01E01 and S01E02 must each be the only regular episode at that season and episode number among episodes that report any of its series IDs. A duplicate file or another show with the same series ID makes the match ambiguous, so mark scenario 10 blocked if one exists. Note whether it also has a special in season 0, a multi-episode file such as `S01E03-E04`, or an episode with no season number.
   - The **unlinked show** is a different show that shares no series ID across the servers. No series ID it reports on one server may appear on any show on the other server, including its own counterpart. On at least one server, its episodes report no episode-level ID. It needs regular episodes S01E01, S01E02, and S01E03 on both servers. For scenarios 13–16, neither server may list multiple regular episodes at the same season/episode coordinate; if it does, mark those count checks blocked. The series show cannot stand in for it, because its episodes already pair by series ID.
   - Continuarr compares every episode in the test libraries, not one show at a time. An episode-level ID that a series show or unlinked show episode reports must not appear on any episode on the other server. A shared ID pairs or blocks the episode before Continuarr compares numbers.
   - **Manual matching** shows only the first episode number of a Jellyfin item. To find multi-episode files on Jellyfin, list the show's episodes with `GET /Users/{userId}/Items?ParentId={seriesId}&Recursive=true&IncludeItemTypes=Episode`, using the Jellyfin user's ID, the show's item ID, and your API key. An item is ranged when its `IndexNumberEnd` is greater than its `IndexNumber`. If you cannot read `IndexNumberEnd`, mark every check that depends on Jellyfin ranges blocked.
4. On Plex, add a Home user and a user with an accepted server grant. Create at least one Jellyfin user. Give the Plex grant user and the Jellyfin user access to the test libraries and no others. Continuarr compares every movie and episode those users can access, so an item in another library can pair with a test item or make it ambiguous.
5. Write down each test item's watched state on both servers so you can restore it later. Then mark every test item unwatched on both servers. A directional scenario proves nothing if its destination already shows the item as watched.
6. Record the Plex Media Server version, the Jellyfin version, and the app revision from `git rev-parse HEAD`.
7. Follow [Run locally](../README.md#run-locally) with an empty database, then create the installation-owner account.

## Scenarios

The test items are movies A, B, and C and episodes A and B. Wait for each run to finish before you check its result.

1. **Import Plex users.** On **Connections & sync**, choose **Sign in to Plex** and authorize Continuarr. Choose **Find Plex servers**, select the server and address, and choose **Save server and import users**. **Users** lists the owner, the Home user, and the grant user.
2. **Connect Jellyfin.** Enter the server URL, including the reverse proxy path if you use one, and an API key. Choose **Connect and import users**. Expect "Jellyfin users imported. Open Users to pair people."
3. **Pair the users.** On **Users**, pair the Plex grant user with the Jellyfin user and choose **Create pairing**. Make every watched change and check below while signed in as these two users.
4. **Plex to Jellyfin.** On Plex, mark movie A and episode A watched. Choose **Preview changes**. It lists both items with "Mark watched on Jellyfin", and both are still unwatched in Jellyfin. Choose **Sync now**. Both become watched in Jellyfin.
5. **Jellyfin to Plex.** In Jellyfin, mark movie B and episode B watched. Confirm that both are still unwatched on Plex. Sync. Both become watched on Plex.
6. **Unwatch does not propagate.** Mark movie A unwatched on Plex and movie B unwatched in Jellyfin. Sync. Neither unwatch clears the other server, and the sync marks both items watched again because watched on either side means watched on both.
7. **Repeat sync writes nothing.** Sync again. The run shows "0 of 0 planned updates applied" and neither server changes.
8. **Hourly sync.** Select **Sync automatically every hour** on the pairing. Mark movie C watched on Plex. Leave Continuarr running for more than an hour. A new run appears without a manual sync, and movie C is watched in Jellyfin. Clear **Sync automatically every hour** afterwards.
9. **Redirects are rejected.** Set up an address that redirects every path to the Jellyfin server. A redirect on the root path alone is not enough because Continuarr requests `System/Info` under the URL you enter. Connect Jellyfin with that address. Expect "The media server redirected this request. Enter the server's final URL." No new server is saved.

## Matching scenarios

These scenarios prove that episodes pair without episode-level IDs. Run them after scenario 9 with the same person pairing. They use **Preview changes** only, which reads both libraries and writes nothing. Do not choose **Sync now**, and keep **Sync automatically every hour** cleared. Write down the preview's **Matched pairs** and skip-reason counts at each step.

If the series show lacks a numbering edge case, record that case as a limitation with the reason and continue. For example, record "no multi-episode file in the test library". If no show fits the series show description, record scenarios 10 and 11 as blocked. If no show fits the unlinked show description, record scenarios 12 to 16 as blocked. Do not loosen a show's description to run a scenario.

10. **Series ID and number pair episodes.** Mark series show S01E01 watched in Jellyfin and S01E02 watched on Plex. Choose **Preview changes**. It lists S01E01 with "Mark watched on Plex" and S01E02 with "Mark watched on Jellyfin". Neither episode needed a manual match.
11. **Specials, absolute numbers, and multi-episode files stay unmatched.** The edge cases are the season 0 special, the multi-episode file, and the episode with no season number. Continuarr pairs a shared episode-level ID before it compares numbers, so an edge-case item with a shared ID would match and would not prove this rule. Before you mark anything, open the series show on both sides in **Manual matching** and check each case:
    - A case qualifies only if none of its items' metadata IDs appears on any episode on the other server.
    - The multi-episode file qualifies only if Jellyfin lists it as one ranged item, with no separate item for its later episodes. Confirm the range with `IndexNumberEnd` as described in step 3. Plex lists each episode of the file as its own item. Count a Plex episode as unsupported only when its displayed file path is shared with another episode from that file. An episode whose path is missing, unique, or different from the other episodes' path counts as unmatched.

    Record a case the series show does not have as a limitation, and record a case that fails a check as blocked. For each qualifying case, mark its items watched on one server. Preview. None of them is listed as a planned write. **Episodes that cannot match by number** includes these unsupported items on each server that lists them: the special, the episode with no season number, the Jellyfin item for the multi-episode file, and each Plex episode of the file whose displayed path is shared with another episode from that file. Continuarr reads the file's episode range on Plex from that shared path. Plex episodes whose paths are missing or not shared count under **Unmatched items** instead.
12. **Unlinked episodes stay unmatched.** Mark unlinked show S01E01 watched on Plex. Preview. S01E01 is not listed as a planned write, and the unlinked show's episodes count under **Unmatched items**. Keep these counts as the baseline for scenarios 13 to 16.
13. **A show match pairs regular episodes.** Before you save, count two numbers for the unlinked show in **Manual matching**. The pair count is the number of regular episodes that appear once on each server with the same season and episode number, outside any multi-episode file. The unsupported count is the number of its unsupported items on both servers, found the same way as in scenario 11. Use `IndexNumberEnd` from step 3 to find ranged Jellyfin items for both counts. If you cannot read it, or Jellyfin lists a multi-episode file in this show as separate items, record the count checks in scenarios 13 to 16 as blocked. Choose **Manual matching**, choose the pairing, and open the **Shows** tab. Select the unlinked show on each side and choose **Save show match**. Expect "Show match saved. Watched status has not changed." Watched status on both servers is unchanged. On the **Episodes** tab, choose the unlinked show in the **Show** filter on each side. Each regular episode with a counterpart reads "Automatic via show match:" followed by the counterpart with the same season and episode number. Specials, multi-episode files, and episodes with no counterpart read "Needs an episode match". Preview. It lists S01E01 with "Mark watched on Jellyfin". Compared with scenario 12, **Matched pairs** rises by the pair count. **Unmatched items** falls by twice the pair count plus the unsupported count, and **Episodes that cannot match by number** rises by the unsupported count.
14. **An episode match overrides the show match.** On the **Episodes** tab, select unlinked show S01E02 on Plex and S01E03 on Jellyfin, then choose **Save manual match**. Expect "Manual match saved. Watched status has not changed." Both items read "Manually matched". Plex S01E03 and Jellyfin S01E02 now read "Needs an episode match". Preview. Compared with scenario 13, **Matched pairs** falls by one and **Unmatched items** rises by two.
15. **Removing the episode match restores the show pairs.** Choose **Remove match** on the saved episode match, then **Confirm removal**. Every episode that read "Automatic via show match:" in scenario 13 reads it again. Preview. The counts equal scenario 13.
16. **Removing the show match unpairs the episodes.** On the **Shows** tab, choose **Remove show match**. The confirmation reads "Remove this saved show match? Watched status will stay as it is. Episodes return to metadata matching." Choose **Confirm removal**. No episode of the unlinked show reads "Automatic via show match:". Preview. S01E01 is no longer listed, and the counts equal scenario 12. Unlinked show S01E01 is still watched on Plex only.

## Record the results

Comment on the verification issue with the server versions, the app revision, and each scenario's before and after watched state, run summary, and pass or fail result. For scenarios 10 to 16, record the preview counts in place of run summaries, and list each recorded limitation and blocked scenario. Leave out server URLs, tokens, usernames, and server IDs. Open a follow-up issue for any provider behavior that differs from this checklist.

## Restore the servers

Stop Continuarr, then return each test item to the watched state you wrote down. This restores watched flags only. The providers may have recorded each sync as a new play.
